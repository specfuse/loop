# Gate 2 — drafting from answers

An answered question issue produces a linted feature folder, with every
defaulted decision recorded as an explicit assumption, and `FeatureProvider`
dispatches this path instead of escalating.

## Definition of done

Drafted by gate 1's `plan-next` from what gate 1's retrospective and lessons
actually establish — deliberately not pre-specified here. The unknown this gate
turns on is **what operators actually answer**, and gate 1 is what produces that
evidence.

The terminal `close` work unit is pre-declared in `PLAN.md` so the linter reads
this gate, not gate 1, as the feature's terminal gate; `plan-next` inserts this
gate's substantive units *before* it.

## Arming discipline

Drafted by gate 1's `plan-next` alongside this gate's substantive units. It
must at minimum carry the runtime-probe result named in `GATE-01.md`'s own
arming discipline — the observed operator reply shape — since every parsing
criterion in this gate depends on it.
